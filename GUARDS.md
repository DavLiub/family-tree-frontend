# Архитектурные стражи

Node22. Versions exact: dependency-cruiser17.3.9 иjscpd4.0.5.
У первого engines.node=`^20.12||^22||>=24`; второй engines не объявляет.
Метаданные проверены в npm registry, runtime проверяется вCI. Запуск из корня frontend: `node scripts/guards/check.mjs`.
Контроль самих стражей: `node --test test/guards/*.test.mjs`.
На VPS тесты не запускать; обе команды включаются в CI техлидом.

- dependency-cruiser17.3.9 строит полный граф src, проверяет циклы,
  неразрешимые импорты, production→test/tool/devDependencies и component→views.
- Дополнительный проход проверяет транзитивные зависимости charts/model и
  charts/layout: запрещены UI-компоненты/страницы/mixins, api/appState,
  Lit/Material, агрегат d3, D3DOM-адаптеры, тесты/инструменты. Чистые D3math/layout
  и Graphviz разрешены. Нынешняя цепочка layout→charts/util→api — legacy,
  а новое использование такой цепочки новым модулем является нарушением.
- AST-проверка чистых model/layout запрещает прямые browser-глобалы
  window/document/fetch/XMLHttpRequest и др., включая globalThis. Имена
  зарезервированы консервативно даже при локальном shadowing. Старые
  обращения учитываются отдельно по файлу/контексту/числу повторов.
- Basename каждого Git tracked и nonignored untracked файла не длиннее48
  Unicode-символов вместе с расширением. Правило включает test/config/fixtures;
  пути каталогов не ограничиваются. Существующие имена укладываются.
- jscpd4.0.5 ищет копии src JS/TS от100токенов и10строк, mode:mild
  (без комментариев). Тестовые фикстуры, документация и сборки не входят
  в production-detector. Процентный бюджет не используется: новая копия
  не компенсируется удалением другой.

## Legacy baseline

Неизменная база: `62cb08af3a0665a728b288828856e43df26a74d7`.
CI должен получить этот commit (checkout fetch-depth:0). Проверка извлекает
его src/package.json/tsconfig.json в уникальный tmp, не меняя рабочую ветку,
и анализирует теми же версиями инструментов и правилами, что текущий код.
Нужны Git и установленные devDependencies, сетевых запросов при анализе нет.
Если база недоступна, отчёт повреждён или инструмент не работает — fail.

Разрешены только прежние точные нарушения: rule/from/to/состав цикла,
цепочка model/layout→запрещённый слой; для копий — пара путей и SHA256
содержимого фрагмента (нормализован только CRLF), с учётом числа повторений.
Новые пути, содержимое копий и увеличение числа повторов fail.
Сдвиг номера строки сам по себе не нарушает baseline; изменение отступов
внутри найденного фрагмента может требовать review, так как hash сохраняет
пробелы строковых литералов.

Отчёты baseline/current/failures сохраняются в `artifacts/guards` дляCI.
Baseline содержит legacy, а не разрешение добавлять их. После сокращения
долга техлид может отдельным review изменить BASE_REF в policy.mjs на
проверенный commit; CI никогда автоматически не увеличивает baseline.
Фиксированная база сама не запрещает возврат старого удалённого нарушения:
для такого запрета baseline нужно продвигать после согласованной очистки.

## Пределы автоматизации

Это статические импорты, в том числе поддерживаемые parserом динамические
литеральные import. Строковые вычисляемые импорты, глобальные DOM/API-вызовы
без импорта в промежуточных helper и функциональное равенство разных
реализаций требуют review. Для чистых model/layout прямые browser-глобалы
проверяются AST.
Транзитивный обход ограничен20000цепочками на модуль, затем явный fail;
каждый внешний анализ ограничен120секундами и64МиБ вывода.
Копии/структурное сходство могут быть замечены по совпадающим токенам;
полное семантическое дублирование произвольных функций не гарантируется.
Изменение инструментов, порогов или baseline — архитектурное решение,
проверяемое отдельно; не ослаблять правила ради зелёного CI.
